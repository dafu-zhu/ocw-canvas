# CMU 36-705 (Intermediate Statistics) — Seed Course Design

**Date:** 2026-05-13
**Status:** Draft for review
**Scope:** Add a second seed course to `backend/seed/`, modeled on `seed_template_course.py` (MIT 18.100B) but adapted to a substantially different source structure (Larry Wasserman's personal CMU page).
**Source:** <https://www.stat.cmu.edu/~larry/=stat705/> · syllabus <https://www.stat.cmu.edu/~larry/=stat705/syllabus.pdf>

---

## 1. Purpose

Seed the second course end-to-end: `CMU 36-705 — Intermediate Statistics`, instructor Larry Wasserman. Like the 18.100B seed, this is an idempotent loader (`python -m seed.seed_cmu_36705 [--force] [--update-urls]`) that builds the Course → Modules → Module Items → Assignment Groups → Assignments tree pointing out to the canonical CMU URLs. Nothing is re-hosted.

The motivation is also pedagogical for the codebase: CMU's source page is structurally different from MIT OCW (no videos, no per-lecture topic labels on the index, no review handouts, irregular filename capitalization), which forces us to exercise and document a *second* seed pattern alongside the 18.100B template.

### 5.2 Test I, Test II, Final Exam

Per syllabus: "tests will just be homework assignments where you will not be allowed to collaborate." CMU posts **no** test or final paper, and **no** review handouts (unlike 18.100B's midterm/final review PDFs).

The seed will create three assignments — Test I, Test II, Final Exam — each with:
- no `external_url` on any module item linking to a source paper
- `description_md` explaining the syllabus's "test = solo HW" rule and recommending that the user either (a) ask the AI to generate fresh problems on the covered material, or (b) pick an unused HW PDF and commit to doing it under solo conditions
- `covers_lecture_from/to`: Test I = 1–7, Test II = 1–18, Final = 1–27 (cumulative, matching where the tests sit on the calendar)

Because there is no source problem PDF, the AI reference-solution pipeline will not auto-run on these three. Grading is manual unless the user attaches a problem PDF themselves in teacher mode.

## 7. URL helpers (Python sketch)

```python
BASE = "https://www.stat.cmu.edu/~larry/=stat705"
HOME = BASE + "/"
SYLLABUS = BASE + "/syllabus.pdf"
PIAZZA   = "https://piazza.com/class/keg3v6nru7z18j"

# Lecture-notes URLs. 27 distinct PDFs but slots 11 and 12 use the "a" variants
# (no plain Lecture11.pdf / Lecture12.pdf exist).
_LEC_FILE: dict[int, str] = {11: "Lecture11a.pdf", 12: "Lecture12a.pdf"}

def _lec_url(n: int) -> str:
    return f"{BASE}/{_LEC_FILE.get(n, f'Lecture{n}.pdf')}"

# Homework URLs. HW1 is lowercase; HW2..HW13 are Title-case.
_HW_FILE: dict[int, str] = {1: "homework1.pdf"}

def _hw_url(n: int) -> str:
    return f"{BASE}/{_HW_FILE.get(n, f'Homework{n}.pdf')}"

LECTURE_NOTE_URLS: dict[int, str] = {n: _lec_url(n) for n in range(1, 28)}
HOMEWORK_URLS:     dict[int, str] = {n: _hw_url(n)  for n in range(1, 14)}
```

## 8. File layout

Single new file: `backend/seed/seed_cmu_36705.py`.

Public surface mirrors `seed_template_course.py`:
- module-level constants (URLs, topics, coverage table, markdown blobs)
- `seed(db, force=False) -> Course`
- `update_urls(db) -> dict` (idempotent in-place URL/description refresh)
- `main()` argparse wrapper exposing `--force` and `--update-urls`

No changes to `app/`, models, migrations, or frontend. Strictly additive.

## 9. Differences from `seed_template_course.py` (cheat sheet)

| Concern | 18.100B (`seed_template_course.py`) | 36-705 (new) |
|---|---|---|
| Videos | Per-lecture `video` items + an all-videos page link | **Dropped entirely** |
| Lecture-notes URL pattern | OCW `/resources/<slug>/` (long hashes) | Plain `~larry/=stat705/LectureN.pdf` with two special-cased slots (11a, 12a) |
| HW URL pattern | OCW `/resources/<slug>/` (uniform) | Mixed: HW1 lowercase, HW2–13 Title-case |
| Exam materials | Midterm/Final each have a review PDF + review video; review_midterm slug ordering | None — tests/final have no review handout and no exam paper |
| Module count | 9 (incl. 1 direct-links + 6 units + 2 exams) | 11 (incl. 1 direct-links + 7 units + 3 exams) |
| Assignment groups | 3 (Problem Sets / Midterm / Final) | 4 (Homework / Test I / Test II / Final) |
| drop_lowest_n on the main group | 1 | 0 (syllabus silent) |
| term_label default | `"Summer 2027"` | `""` (user undecided) |
| Per-lecture topic titles available on index | Yes (visible on OCW calendar page) | No (only in the syllabus PDF's Tentative Calendar) |

## 10. Testing

No new pytest cases are required for v1 — `seed_cmu_36705` is invoked manually (and there's no precedent for testing `seed_template_course.py` either). Sanity checks at implementation time:

1. `uv run python -m seed.seed_cmu_36705 --force` against a local SQLite DB; print summary (modules / items / assignments counts).
2. `uv run python -m seed.seed_cmu_36705 --update-urls` is a no-op the second time (idempotency).
3. Spot-check 5–10 emitted URLs by HEAD-fetching them (especially the `Lecture11a` / `homework1` edge cases).
4. CI (`uv run pytest -q`, `uv run ruff check .`) must still pass — the new file should be lint-clean.

## 11. Open / deferred

- **Lecture-note → topic title mapping is an educated guess.** I have only verified `Lecture1.pdf` (Random variables / Concentration review). The unit titles in §6 reflect the syllabus calendar's *session-level* labels, which is the right granularity for self-study even if the individual PDF titles diverge slightly. If a future user wants per-LN titles, they can be filled in by skimming each PDF and editing in teacher mode.
- **No automated test coverage** for either seed (matches existing convention). Worth revisiting once we have ≥3 seed courses.
- **Term label is empty by design.** The user will set it in teacher mode when they pick a self-study term.

## 12. Out of scope for this change

- No new ORM models or migrations.
- No backend API changes.
- No frontend changes (the existing Dashboard / Course / Modules / Assignments / Grades pages render the new course automatically).
- No re-organization of `seed_template_course.py`; the two seed files coexist with duplicated boilerplate, which is fine for two courses. Extract a shared `seed/_base.py` only if a third seed makes the duplication painful.
