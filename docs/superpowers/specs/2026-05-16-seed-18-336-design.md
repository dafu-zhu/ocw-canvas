Date: 2026-05-16

## Goal

Add a seed script that mirrors MIT OCW's only published offering of 18.336 —
**Benjamin Seibold, Spring 2009** — into the OCW Canvas database. This is the
"Numerical PDEs" slot in the JHU-replacement study plan, slated for 2029 in
the user's sequencing.

## Conflict with study plan memory

The `study-plan-jhu-replacement` memory points at "MIT 18.336 (Steven
Johnson), Spring 2023 offering, Krylov/spectral/modern iterative." Verified
on OCW: **no such offering exists.** Johnson's 18.336 materials live on his
personal/MIT-Math pages, not OCW. The only published OCW 18.336 is Seibold
Spring 2009 (`/courses/18-336-numerical-methods-for-partial-differential-equations-spring-2009/`).
The Krylov/spectral/iterative content the user wanted is well-represented in
Seibold's syllabus anyway — Lec 7–12 cover spectral methods, multigrid, and
Krylov. Decision (user-approved): seed Seibold's offering, and update the
memory note to reflect what OCW actually publishes.

Mirrors the natural arc of the syllabus, per the user's chosen option in
brainstorming. Per-lecture note items show the readings mapping verbatim
from OCW's Readings page, plus a link to the lecture-note PDF. No video
items (this offering has no recorded videos).

1. **Direct links** (8 items) — home, syllabus, calendar, readings, lecture-notes index, assignments index, projects index, MATLAB files index.
2. **Unit I — Foundations** (Lec 1–4, 4 items)
3. **Unit II — Elliptic problems & solvers** (Lec 5–12, 8 items; Lec 8 has no PDF)
4. **Unit III — Time-dependent problems** (Lec 13–22, 10 items; Lec 20 has no readings, Lec 21–22 reference notes-only resources)

Per-lecture note items use `kind="note"`. Body format:

```
**Lec N — <topic>**

Readings: <chapter mapping verbatim from OCW>

[Lecture notes PDF →](/resources/mit18_336s09_lecN/)
```

When no readings are listed (Lec 8, 20, 25): omit the Readings line. When no
PDF is published (Lec 8, 26): omit the PDF link. Lec 26 (project
presentations) is not a content lecture and is not included in any module.

## Existing backend machinery used

- `assignment.requires_solution_key` (alembic 0006, shipped 2026-05-15).
- `services.ai_jobs.resolve_key` returns `"project"` when the flag is False
  and there's no key — grading then uses `PROJECT_KEY_NOTE` instead of
  comparing to a reference.
- `services.ai_jobs.run_solution_generation` short-circuits with
  `sol.status = "not_required"` when the flag is False.

No backend changes are needed. The seed is purely additive.

## CLI surface

```
cd backend && uv run python -m seed.seed_18_336 [--force] [--update-urls]
```

- Default: idempotent seed (no-op if course exists).
- `--force`: delete + reseed (loses any submissions / AI solutions /
  announcements on this course).
- `--update-urls`: refresh module-item URLs and assignment
  description_md/coverage in place. Same semantics as `seed_18_065.update_urls`.

**No `--refresh-solutions` flag.** There are no official-solution PDFs to
download — the AI generates the key for each PSet on first grading attempt,
and the project has no key at all.

## Tests — `backend/tests/test_seed_18_336.py`

Pattern follows `test_seed_18_065.py`. Uses the sqlite-backed fixture from
`tests/conftest.py`. Assertions:

1. Course row created with `code="MIT 18.336"`, `term_label="Summer 2029"`,
   `instructor="Dr. Benjamin Seibold"`.
2. Six modules in expected order; Unit I has 4 items, Unit II has 8, etc.
3. Six assignments: 5 PSets with `requires_solution_key=True`, 1 project
   with `requires_solution_key=False`. PSet coverage ranges match the spec.
4. Two AssignmentGroups with weights 50 / 50 summing to 100.
5. Idempotent re-run is a no-op (no second course created, no extra modules).
6. `--force` deletes and reseeds — final count unchanged.
7. `update_urls` rewrites a corrupted module-item URL back to the canonical
   one, leaves an unrelated assignment description untouched.
8. No real network call: tests should not hit OCW. The seed itself does not
   download anything in the no-solutions case, so this should be naturally
   true — assert by monkeypatching `httpx.get` to raise.
